01 · What is it?

Identity, productivity services and one API gateway

Microsoft services

Microsoft 365

The employee workloads: Outlook mail and calendar, Teams, OneDrive, SharePoint and related collaboration services.

API layer

Microsoft Graph

A protected API gateway to Microsoft cloud data. Aura calls resource endpoints only after Microsoft identity authorizes the app. [1]

Identity layer

Microsoft Entra ID

The customer identity and access service. It registers Aura, signs users in, issues tokens and controls consent and access policy. [2]

Simple distinctionMicrosoft 365 holds the work data. Microsoft Graph is the API door. Entra proves who Aura is and what it may do. Graph is not a separate data store.

04 · How to integrate

Connect directly to Graph through Entra; add middleware only for a clear need

Aura can call Microsoft Graph over HTTPS and authenticate with Entra ID using OAuth 2.0 and OpenID Connect. Microsoft Graph SDKs can simplify token use and API calls; Graph Explorer is the quickest place to prove scopes and responses before coding. No middleware is required for the first pilot. [1][2][15]

Integration optionHow it worksDecision
Direct Graph + Entra SSORegister Aura in Entra, sign employees in through OIDC, then call Graph from the Aura backend with HTTPS or an SDK.Recommended Simplest and lowest-cost starting point.

A · Setup and onboarding checklist

Prove the calls

Get a test tenant or trial and use Graph Explorer to validate the exact endpoints and returned fields.

Register Aura

Create the Entra app, approved OIDC redirect URIs and a server credential; prefer a certificate for production and assign an owner.

Choose access

Use delegated permissions for employee features and application permissions only for approved background jobs.

Request minimum scopes

Start with only what the journey needs, such as User.Read, Calendars.Read and Files.Read; include offline_access only when refresh tokens are required.

Obtain consent

Record tenant-admin approval where required; it is always required for application permissions and selected high-privilege delegated scopes.

Build the runtime

Implement OIDC sign-in and server-side token handling, then add paging, throttling, audit events and optional change notifications.

Test and release

Verify in non-production, then launch with monitoring, revocation support and certificate/secret rotation.

Proposed architecture. Tokens and app credentials stay on the server. Aura requests only the fields needed for the screen, applies tenant isolation, stores the minimum necessary data and links users back to Microsoft 365 for full content where possible.

Tenant pattern must be chosen deliberatelyFor a dedicated customer deployment, a single-tenant registration gives the clearest isolation. If one shared Aura SaaS app serves several companies, configure it as multi-tenant: every customer grants consent in its own tenant, tenant IDs must be isolated in data and logs, and publisher verification should be completed to build administrator trust. 06 · Access, prerequisites & blockers

Buildable only with a customer tenant and named administrators

Confirm before build

Customer prerequisites

  • Microsoft 365 tenant and licensed pilot users for the selected workloads.
  • Entra application owner plus an administrator able to review and grant consent.
  • Non-production test users, calendars, documents and approved Teams destinations.
  • Security/privacy owner, data classification, retention and audit requirements.
  • Saudi Microsoft/CSP confirmation of product, licensing and regional terms.
Delivery controls

Recommended guardrails

  • Choose single-tenant per customer or a verified multi-tenant SaaS registration deliberately; isolate every tenant and keep separate credentials per environment.
  • Prefer delegated access for employee screens; avoid broad tenant-wide application roles.
  • For app-only mail/calendar access, use an approved resource scope such as Exchange Application RBAC. [9]
  • Exclude beta endpoints and bulk extraction from the first release.
  • Keep tokens, secrets and sensitive content out of browser storage and application logs.

07 · Cost

No blanket per-call charge for standard Graph APIs

Microsoft states that standard APIs within defined usage thresholds are available as part of the user license. If a customer already has the required Microsoft 365 plans, Graph access, Entra sign-in and the app registration usually add no separate subscription fee. The customer still needs the relevant workload and identity entitlements, and a small set of APIs/services has separate metered rules. [10][15]

Existing Microsoft rights

Confirm licenses for each pilot user and workload. Do not buy a new suite until current entitlements are checked.

Aura delivery

Budget for discovery, security review, implementation, testing, hosting, monitoring and support.

Exceptions and add-ons

Budget only if the selected API is metered or the journey needs extra Azure, Entra or Microsoft 365 capability.
